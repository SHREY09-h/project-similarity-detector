# Backend Guide

This document explains the backend files, how an API request moves through them, and how to run and test the service.

## What the backend does

The backend is a FastAPI service. It stores project records in a SQLAlchemy database, accepts a submitted project and optional report/source files, compares it against the stored projects, and returns the highest-ranked matches with score details and evidence. It does not execute uploaded source code, and a similarity score is decision support rather than an automatic plagiarism finding.

## Files

| File | Responsibility |
| --- | --- |
| `app/main.py` | Creates the FastAPI app; enables CORS; defines request/response models and API routes; validates and extracts uploaded reports and source archives; runs comparisons and stores analysis results. |
| `app/database.py` | Reads `DATABASE_URL`, creates the SQLAlchemy engine/session factory/base class, and provides a request-scoped database session. SQLite is the default. |
| `app/models.py` | Defines the database tables: `Project` (repository entries), `Analysis` (submitted-analysis summary), and `SimilarityResult` (ranked candidate details). |
| `app/seed.py` | Supplies ten demonstration projects at startup, but only when the projects table is empty. |
| `app/similarity/engine.py` | Implements text cleanup and tokenization, TF-IDF cosine similarity, Jaccard overlap, MinHash shingles, code normalization, component weighting, classification, and evidence generation. |
| `app/similarity/ollama.py` | Optionally calls a local Ollama service for abstract embeddings and semantic similarity; caches results and gracefully reports unavailable results so the engine can fall back to TF-IDF. |
| `app/similarity/__init__.py` | Exposes `compare_projects` and `classify` from the similarity engine package. |
| `app/__init__.py` | Marks `app` as a Python package; currently contains no other code. |
| `tests/test_similarity.py` | Unit tests for text processing, similarity algorithms, scoring/classification, absent optional evidence, Ollama behavior, and fallback behavior. |
| `requirements.txt` | Pins the Python libraries used by the API, database, file parsing, similarity engine, and tests. |

`similarity.db` is the default local SQLite database and is created/updated when the service starts. `.venv/` contains the local Python environment, and `.pytest_cache/` is generated by pytest; these are runtime/development artifacts, not application modules.

## Request and startup flow

1. Uvicorn imports `app.main:app` and starts the FastAPI application.
2. The application lifespan creates database tables and calls `seed()` if there are no projects yet.
3. FastAPI validates route inputs. Database routes receive a session from `get_db()` and close it after the request.
4. For an analysis, `main.py` reads the form and optional uploads. PDF/TXT reports become text; supported source files become text; ZIP uploads contribute up to 50 supported source files, each under 1 MB.
5. Each stored project is passed with the submitted project to `compare_projects()` in `engine.py`.
6. Candidate results are sorted by score. The top ten are stored in `analyses` and `similarity_results`; the response to the submission contains the analysis ID, overall score, and classification.
7. A later GET request retrieves the analysis summary and ranked results, including the candidate project summary, score components, shared terms, and explanatory evidence.

## API routes

Interactive API documentation is available at `/docs` while the server is running.

| Method and path | Purpose |
| --- | --- |
| `GET /` | Basic service information and links to docs/health. |
| `GET /api/health` | Health check; returns `status: healthy` when the API responds. |
| `GET /api/algorithms` | Lists the similarity approaches presented by the service. |
| `GET /api/projects` | Lists projects; optional `search`, `category`, and `year` filters; `sort` accepts `newest`, `oldest`, or `title` (default `newest`). Search checks title and abstract. |
| `POST /api/projects` | Adds a project using a JSON `ProjectIn` body. Title must be 3-240 characters and abstract 20-2000 characters. Other fields include description, keywords, category, academic year, team name, report text, and source code. Returns the stored project with its ID and creation time. |
| `GET /api/projects/{project_id}` | Gets one project; returns 404 if it does not exist. |
| `DELETE /api/projects/{project_id}` | Deletes one project; returns 404 if it does not exist. |
| `POST /api/analysis` | Accepts multipart form data, compares it with every stored project, saves the analysis and top ten matches, and returns the new analysis ID and top-match score/classification. |
| `GET /api/analysis/{analysis_id}` | Gets an analysis and its ranked results; returns 404 if missing. |
| `GET /api/analysis/{analysis_id}/results` | Alias for the analysis-detail route above. |

The analysis form requires `title` (3-240 characters) and `abstract` (20-2000 characters). Optional text fields are `keywords` (comma-separated), `description`, `category`, `academic_year`, and `team_name`. Optional uploads are `report` and `source`:

- Reports accept `.pdf` and `.txt`, with a maximum upload size of 10 MiB.
- Source uploads accept `.py`, `.js`, `.jsx`, `.ts`, `.tsx`, `.java`, `.cpp`, `.c`, `.h`, `.cs`, or `.zip`, with a maximum upload size of 5 MiB.
- ZIP processing reads at most 50 supported, non-directory files smaller than 1 MB each. Source is decoded as text and is never executed.

If there are no stored candidate projects, analysis still completes with a low-similarity score and no ranked results.

## How similarity is calculated

For every submitted/candidate pair, the engine calculates these component scores, each between 0 and 1:

| Component | Weight | How it is calculated |
| --- | ---: | --- |
| Title | 0.10 | TF-IDF cosine similarity of the titles. |
| Abstract | 0.25 | Ollama embedding cosine when available; otherwise TF-IDF cosine of abstract plus description. |
| Report | 0.20 | TF-IDF cosine of report text, only when both projects have report text. |
| Keywords | 0.15 | Jaccard overlap of keyword tokens. |
| MinHash | 0.10 | Similarity of 64 MinHash signatures over three-token shingles from abstract/description and report text. |
| Code | 0.20 | Average of TF-IDF cosine and Jaccard after comments are removed and identifiers are normalized; only when both projects have source code. |

Unavailable report or code components are omitted and the remaining weights are renormalized. They are not counted as zero. Text tokenization lowercases text, removes a small stop-word list, and ignores one-character tokens. Evidence messages are generated from component-specific thresholds; shared keywords are the first ten sorted terms shared between query and candidate text/keywords.

The overall score is classified as follows:

| Score | Classification |
| ---: | --- |
| 0.85-1.00 | Very High Similarity |
| 0.70-0.8499 | High Similarity |
| 0.50-0.6999 | Significant Similarity |
| 0.25-0.4999 | Moderate Similarity |
| Below 0.25 | Low Similarity |

## Ollama and fallback behavior

Ollama is controlled by these environment variables:

| Variable | Default | Meaning |
| --- | --- | --- |
| `OLLAMA_ENABLED` | `true` | Set to `false`, `0`, `no`, or `off` to disable Ollama. |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | Ollama server base URL. |
| `OLLAMA_MODEL` | `nomic-embed-text` | Model used for the embedding endpoint. |
| `OLLAMA_TIMEOUT` | `8` | Per-request timeout in seconds. |

If embeddings cannot be retrieved or do not match, the Ollama module tries its generated semantic comparison, using `qwen2.5-coder:7b` by default. If Ollama is disabled, unavailable, or returns an unusable response, the abstract comparison falls back to local TF-IDF cosine. The rest of the comparison engine is local.

## Database tables

- `projects` stores repository project fields, including optional report text and source code.
- `analyses` stores the submitted title and metadata plus the top-match score and classification.
- `similarity_results` stores the rank, score, classification, component scores, shared keywords, and evidence for each candidate returned in the top ten.

The default database URL is `sqlite:///./similarity.db`. Because that path is relative to the process working directory, run Uvicorn from the `backend` directory to use `backend/similarity.db`. Set `DATABASE_URL` to use another SQLAlchemy-supported database. `CORS_ORIGINS` is a comma-separated allowlist; by default it allows `http://localhost:5173` and `http://127.0.0.1:5173`.

## Run on Windows

From the repository root, activate or use the project virtual environment, then start the API:

```powershell
cd backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Install dependencies if needed:

```powershell
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

The API is at `http://127.0.0.1:8000`; interactive docs are at `http://127.0.0.1:8000/docs`.

Run backend tests from the `backend` directory:

```powershell
..\.venv\Scripts\python.exe -m pytest tests -q
```
